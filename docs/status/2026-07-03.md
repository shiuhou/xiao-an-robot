# Status 2026-07-03

## Demo 1 base-station mic to real OpenClaw route

Scope: correct Demo 1 from the temporary local-rule route to the intended
OpenClaw-owned decision path.

Current main path:

```text
DK-2500/base-station USB mic or mock transcript
-> tools/demo/demo1_usb_mic_to_agent_screen.py
-> SenseVoice ASR transcript
-> runtime/demo1_openclaw_context.json
-> GatewayOpenClawAdapter
-> OpenClaw Gateway ws://127.0.0.1:18789
-> xiaoan-runtime decision
-> ActionExecutor
-> ws://127.0.0.1:8765/agent
-> base_station /control
-> robot/mergetesting
```

Implementation updates:

- `tools/demo/run_demo1_mic_to_robot.sh` now defaults to `--route-openclaw`.
- `--route-openclaw` sends a fixed `asr.transcript` event to real OpenClaw
  Gateway / `xiaoan-runtime`.
- `runtime/demo1_openclaw_result.json` records the Gateway response, parsed
  `OpenClawDecision`, tool-call validation, and `ActionExecutor` result.
- `runtime/demo1_action_plan.json` is no longer the main decision artifact for
  the OpenClaw route; it records `route=openclaw_gateway` and no local actions.
- `--route-agent` remains available only as a legacy local-rule diagnostic path.
- Demo 1 validates OpenClaw tool calls before execution. Allowed tools:
  `xiaoan.robot.expression`, `xiaoan.robot.care`, `xiaoan.robot.move_out`,
  `xiaoan.robot.say`.
- Allowed expressions are the Python `/agent` enum and `robot/mergetesting`
  shared set: `happy`, `sad`, `caring`, `tired`, `thinking`, `speaking`,
  `idle`, `surprised`, `sleeping`.
- The OpenClaw request now sends a Demo 1 filtered tool manifest, not the full
  Xiao An tool list.
- `validate_openclaw_decision()` rejects reply-text-only decisions, unhandled
  decisions, unsupported tools, and unsupported expressions.
- `runtime/demo1_openclaw_result.json` is considered successful only when a
  validated OpenClaw tool call produces at least one executed `tool_call`
  action; `/agent` ack or `reply_text` alone is not enough.
- `RobotMotionSkill.care_for_user()` now uses the reliable
  `audio.play_local care_01` path for the care tool's audio step instead of
  depending on spoken TTS.

1. `openclaw_context.allowed_actions`
2. Demo 1 action/OpenClaw validation
3. `/agent -> /control` translator in `base_station/ws_server/protocol.py`
4. `robot/mergetesting` firmware protocol and face240 mapping

Verified focus expressions:

- `happy`
- `caring`
- `thinking`
- `surprised`

Robot-side evidence from USB serial during expression checks:

```text
[WS] Rx control: display.expression
[Router] Dispatch: display.expression
[WS] command.ack display.expression -> ok
```

`angry` is not a supported protocol expression and is not a main demo target.
It must not be treated as a silent success fallback in Demo 1; unsupported
expression output from OpenClaw is a validation failure.

  - `Command ack: type=motion.execute status=ok`
  - `Motion completed: ... -> success`

  `AUDIO_UNSUPPORTED: speaker not ready` when local sound followed accepted
  TTS immediately.
